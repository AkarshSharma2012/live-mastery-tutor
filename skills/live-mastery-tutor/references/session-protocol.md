# Session protocol

Use this protocol when teaching or reviewing. State controls topic selection; this file controls interaction quality.

## Session brief

Before speaking, establish:

- Minutes available
- Due reviews
- One primary objective
- One practical outcome
- The learner's active misconception or nearest confusable concept
- The stopping condition

Open with a payoff or a concrete problem. Avoid opening a new topic with a scored quiz. A prediction before instruction is diagnostic material, not a failure.

## Microcycle

### Retrieve

Ask due review questions cold. Use new wording and a different surface scenario. Record:

- `independent_correct`
- `prompted_correct`
- `incorrect`
- Confidence from 1–5 when calibration matters

Immediate correction does not convert the original attempt to correct.

### Explain

Teach one concept. Define each term before using it as a premise. Prefer this order:

1. Plain-language model
2. One concrete example
3. Boundary or counterexample
4. Contrast with the closest confusing idea
5. Procedure or decision rule

Change representation when reteaching. Repeating the same paragraph more slowly is not a new explanation.

### Practice

Choose the strongest available evidence:

1. Authentic task in the real or safe practice environment
2. Simulation with observable output
3. Worked scenario requiring a decision and justification
4. Recall question only when the objective is declarative

Before potentially consequential commands, ask the learner to predict the effect. Use a disposable practice target whenever possible.

### Teach-back

Ask the learner to explain the idea in their own words to a smart beginner. Probe missing causal links and boundaries. Do not accept copied phrasing from the immediately preceding explanation as independent evidence.

### Assess

Ask one item at a time. A topic set should normally contain:

- One retrieval item
- One application scenario
- One contrast or misconception item
- One transfer item when the learner is ready

Multiple-choice options must all be plausible. Written justification is stronger evidence than selecting a letter. Avoid trivia, negative wording, and clues created by one unusually long option.

## Feedback

After each answer:

1. Give the verdict.
2. State the evidence in the learner's answer.
3. Correct the exact gap.
4. Ask the next question or choose the remediation.

Separate:

- **Recall gap:** previously understood but not retrievable → prompt, then schedule sooner.
- **Model gap:** causal explanation is wrong → rebuild the model with a different representation.
- **Discrimination gap:** two ideas are conflated → contrast table or paired cases.
- **Execution gap:** knows what but cannot do → another task with less scaffolding.
- **Calibration gap:** confidence and performance disagree → ask for confidence and reasoning more often.

## Difficulty control

- Below 60% independent: reduce scope and reteach.
- 60–79%: targeted practice; do not advance to mastery.
- 80–94%: advance while scheduling retrieval.
- 95–100% twice: increase transfer, ambiguity, and interleaving.

Do not use the threshold mechanically when the assessment is too small or badly targeted. Note the limitation instead of pretending to have precision.

## Session close

The tutor closes after the primary objective has an application attempt and the planned exit retrieval is graded, or when time expires. Close with:

- Demonstrated today
- Still uncertain
- First-attempt score, separate from corrected score
- Next review date or trigger
- One small next action
- Next-session hook

Persist before claiming success. A session may close while the learner continues asking questions afterward.
